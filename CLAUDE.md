# StudyPulse – project rules

StudyPulse – Smart Study Load & Burnout Prevention System. A Java desktop app
(university project) that lets students plan study tasks, calculates a Study Load
Index and a Burnout Risk Score, and gives early warnings and recommendations.
It is built in 10 parts. **Every part must follow all rules below.**

## Project type
- NetBeans "Java with Ant" project. Keep `build.xml`, `manifest.mf`,
  `nbproject/project.xml`, `nbproject/project.properties` in the standard layout.
  `nbproject/build-impl.xml` and `genfiles.properties` are generated by NetBeans – never edit them.
- Developed with NetBeans 8.2 and JDK 1.8.0_111.
- Main class: `studypulse.Main` (`main.class` in project.properties).

## Java 8 ONLY
- `javac.source=1.8`, `javac.target=1.8`.
- Forbidden: `var`, records, text blocks, switch expressions, `List.of` / `Set.of` / `Map.of`,
  `String.isBlank` / `strip` / `repeat` / `lines`, `Optional.isEmpty`, `Stream.toList()`,
  `Files.readString`, and any other API added after Java 8.
- Use `trim().isEmpty()`, `new ArrayList<...>()`, `Collections.unmodifiableList`, anonymous classes or lambdas.

## UI rule: JFrame Forms ONLY
- Every screen is a NetBeans **JFrame Form**: `Xxx.java` + `Xxx.form` with the same name in
  `studypulse.forms`, exactly like NetBeans "New > JFrame Form", so Design view opens it.
- Generated code lives only inside `//GEN-BEGIN:initComponents` … `//GEN-END:initComponents`
  (and the `//GEN-BEGIN:variables` block). The `.form` XML must match that code exactly:
  same component names, properties, layout. Layout = GroupLayout (Free Design),
  `FormSettings_layoutCodeTarget=1`, fully qualified names (`generateFQN=true`).
- When changing a form, change **both** the `.form` and the generated code together.
- Own logic (loading data, validation, event handler work) goes OUTSIDE the guarded blocks in
  normal private methods. Event handler bodies (between `GEN-FIRST`/`GEN-LAST`) only call those methods.
- No JPanel pages, no CardLayout screens, no JInternalFrame. Navigation = open the next
  JFrame Form and `dispose()` the current one.
- Pop-up messages: `JOptionPane` only.
- Every frame: `setLocationRelativeTo(null)` (form property *Generate Center* = true),
  title `"StudyPulse – <Screen>"` (en dash).
- Component names use prefixes: `txtEmail`, `pwdPassword`, `btnSave`, `tblTasks`, `cmbDifficulty`,
  `lblRiskScore`, `chkWellbeing`, `spnMinutes`, `dtcDeadline`, `scrTasks`, `pnlSidebar`, `txaNote`.
- After `initComponents()` the constructor calls `applyTheme()` (UITheme helpers) and the load methods.
- Fixed-size frames use form size policy "Generate Resize Code" (`formSizePolicy=0` + `formSize`),
  which generates `setSize(new java.awt.Dimension(w, h)); setLocationRelativeTo(null);`.
- Forms show user-fixable errors in a red `lblError` (`UITheme.styleErrorLabel / showError / hideError`)
  or a `JOptionPane`; services throw `ServiceException` whose message is shown as it is.

## Authentication
- `LoginFrame` (400x540) is the first frame; `SignupFrame` (400x640). Both not resizable.
- `AuthService.register(fullName, email, password[], confirm[], wellbeing)` validates, stores the user
  and 7 `availability` rows in one transaction (day 1-7, 180 min, Friday = 0), and logs in.
  `AuthService.login(email, password[])` → wrong email or password: "Email or password is incorrect."
- Emails are stored trimmed and lower-case. Passwords: `PasswordUtil` (SHA-256, random 16-byte salt,
  Base64); never store or log plain text; read passwords as `char[]` and clear them after use.
- `Session.getUser() / setUser() / logout() / getUserId()` holds the logged-in user.

## Database (SQLite)
- File: `data/studypulse.db` next to the project (run from NetBeans) or next to
  `StudyPulse.jar` (run from `dist/`). `DBConnection` creates the folder if missing.
- Schema: `src/studypulse/resources/schema.sql`, run at every start
  (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`). Change the schema only there.
- `PRAGMA foreign_keys = ON` on every connection (done in `DBConnection.getConnection()`).
- Dates are TEXT `yyyy-MM-dd`, date-times TEXT `yyyy-MM-dd HH:mm:ss` – always via `DateUtil`.
  `tasks.deadline` is a date-time (`Task.getDeadline()` is a `LocalDateTime`, picked with
  JDateChooser + an `HH:mm` spinner); text comparison (`deadline < ?`) works because of the format.
  Display: `DateUtil.formatLong` (`Monday, 02 Nov 2026`), `formatDay` (`Mon 02 Nov`),
  `formatShort` (`yyyy-MM-dd HH:mm`), `formatCompact` (`05 Nov 23:59`),
  `formatMinutes` (`2h 30m`).
- Weekdays (`day_of_week`, `rest_day`): 1 = Monday … 7 = Sunday (`java.time.DayOfWeek.getValue()`).
- Enum columns store `Enum.name()`; read back with `Enum.valueOf`. Enum `toString()` is the display label.
- Booleans are INTEGER 0/1.

### ID rule (very important)
- The FIRST column of every table is `id INTEGER PRIMARY KEY AUTOINCREMENT`
  (ids 1, 2, 3 … never reused).
- Never insert an id by hand; read the new id with `getGeneratedKeys()` (`DaoUtil.readGeneratedId`).
- Every foreign key column (`user_id`, `task_id`) has its own `CREATE INDEX`.
- Every JTable showing table rows has **"ID" as its first column** (narrow, centered):
  build the model with `TableUtil.install(table, "Col1", "Col2", ...)` / `TableUtil.createModel(...)`,
  get the selected row's id with `TableUtil.getSelectedId(table)`.
  One editable column: `TableUtil.createModel(editableColumn, Double.class, ...)` (+ a cell editor
  such as `SpinnerCellEditor`). Grids that are not database rows (the study plan week grid)
  are the only exception to the ID rule.

### Tables
1. `users(id, full_name, email UNIQUE, password_hash, salt, created_at, wellbeing_enabled DEFAULT 1, rest_day DEFAULT 5)`
2. `availability(id, user_id, day_of_week 1-7, free_minutes)`, UNIQUE(user_id, day_of_week)
3. `tasks(id, user_id, title, description, task_type ASSIGNMENT/EXAM/PROJECT/PREPARATION, course_name, difficulty EASY/MEDIUM/HARD, estimated_minutes, actual_minutes DEFAULT 0, deadline, priority LOW/MEDIUM/HIGH, status PENDING/IN_PROGRESS/DONE/MISSED, created_at, completed_at)`
4. `plan_blocks(id, user_id, task_id, plan_date, planned_minutes, status PLANNED/DONE/SKIPPED)`
5. `study_logs(id, user_id, task_id NULL, start_time, end_time, duration_minutes, breaks_taken)`
6. `checkins(id, user_id, checkin_date, stress_level 1-5, energy_level 1-5, mood_level 1-5, sleep_hours REAL, note)`, UNIQUE(user_id, checkin_date)
7. `risk_snapshots(id, user_id, snapshot_date, workload_index, burnout_score, risk_level LOW/MODERATE/HIGH/SEVERE, reasons)`, UNIQUE(user_id, snapshot_date)
8. `notifications(id, user_id, type WORKLOAD/BURNOUT/BREAK/DEADLINE/INFO, message, created_at, is_read DEFAULT 0)`
9. `user_settings(id, user_id UNIQUE, focus_minutes DEFAULT 25 (1-90), short_break DEFAULT 5 (1-30),
   long_break DEFAULT 15 (5-60), notifications_on DEFAULT 1, tray_on DEFAULT 1, theme LIGHT/DARK DEFAULT 'LIGHT')`
   – created at sign-up (same transaction); for older users `SettingsService.getSettings()` creates it
   the first time it is needed.

New tables: add them at the END of schema.sql with `CREATE TABLE IF NOT EXISTS` (+ index on every
FK column), so existing databases get them on the next start.

CHECK constraints on all 1-5 values and enum values; `FOREIGN KEY … ON DELETE CASCADE` to users and tasks.

### DAOs
One per table: `UserDAO, AvailabilityDAO, TaskDAO, PlanBlockDAO, StudyLogDAO, CheckinDAO,
RiskSnapshotDAO, NotificationDAO, UserSettingsDAO` (`findByUser`). Each has
`insert` (returns new id and sets it on the object), `update`, `delete`, `findById`,
`findAllByUser` (`UserDAO` has `findAll` / `findByEmail`). Always `PreparedStatement`
+ try-with-resources, one connection per call, methods throw `SQLException`.
For a transaction, add an overload taking a `Connection` (see `UserDAO.insert(Connection, User)`)
and let the service open the connection, `setAutoCommit(false)`, commit / rollback.

## Theme (`UITheme`)
Light and dark mode (Part 9). ACCENT / SUCCESS / WARNING / DANGER / ORANGE_RED / PURPLE / TEAL
and `WHITE` (text on coloured buttons) are fixed. `SIDEBAR, BACKGROUND, SURFACE` (cards, panels,
table rows, chart background), `TEXT, TEXT_MUTED, GRID, HEADER_BACKGROUND, TRACK, ROW_*,
REST_DAY_BACKGROUND, TODAY_BACKGROUND` are theme fields that `UITheme.switchTheme(dark)` changes:
- Always read them at use time (renderers, charts, styling methods); never copy them into constants
  and never use `Color.WHITE` / fixed light colours for backgrounds – use `SURFACE`.
- Forms may keep the light colours in the .form (34,48,63 text, 255,255,255 panels, F4F6F9 …):
  `UITheme.applyFrame(this)` (first line of every `applyTheme()`) runs `recolor()`, which maps
  them to the current theme. `switchTheme` calls `FlatLaf.updateUI()` and `recolor()` for every
  open window. A new light colour that must change in dark mode needs a {light, dark} pair in UITheme.
- The saved theme (`user_settings.theme`) is applied right after login (LoginFrame).

### Table renderers (util)
- `RowColorRenderer(rowColorProvider).installOn(table)` – colors whole rows (by model row index),
  keeps column 0 (ID) centered. Call after `TableUtil.install(...)`.
- `BadgeRenderer(rowColorProvider, badgeColorProvider)` – shows a cell as a colored pill
  (difficulty, risk level, ...). Set it on one column after `installOn`.
- Keep a `List<...> shownXxx` parallel to the table rows so providers can look up the object.

### Form conventions (from Part 3)
- Combo boxes in forms hold display strings in **enum order**; convert with
  `Enum.values()[cmb.getSelectedIndex()]` / `cmb.setSelectedIndex(e.ordinal())`.
  Filter combos have "All ..." at index 0 (enum = `values()[index - 1]`).
- Combos use `JComboBox<String>` (form AuxValue `JavaCodeGenerator_TypeParameters` = `<String>`).
- Things the form editor cannot set (SpinnerDateModel, DocumentListener for live search,
  ListSelectionListener on tables, placeholders) are done in a `setupFields()` / `setupTable()`
  method after `initComponents()`.
- Left form panel `pnlForm` uses `UITheme.styleCard`. Save is for new rows; Update / Delete
  need a selected row (`updateButtons()`); Clear deselects.
- Service validation errors (`ServiceException`) are shown with `JOptionPane` WARNING_MESSAGE.
- `WarningCellRenderer(rowColors, warningProvider).installOn(table)` – single cells in red bold
  (rowColors may be null = white rows).
- Rating scales = `JToggleButton`s in a `ButtonGroup` (form NonVisualComponents, `grpXxx`);
  keep them in an array in the constructor, level = index + 1, 0 = none selected.

## Tasks (Part 3)
- `TaskService` holds all task logic, `TaskDAO` the SQL. Every `TaskService` method works on
  `Session.getUserId()` and checks ownership.
- Opening `TaskFrame` (and every refresh) runs `markOverdueAsMissed()`: PENDING / IN_PROGRESS
  tasks with a passed deadline become MISSED. Updating a MISSED task to a future deadline makes
  it PENDING again.
- Mark Done: status DONE + `completed_at`, then asks for real minutes → `actual_minutes`
  (0 = unknown, ignored by statistics).
- `suggestEstimate(difficulty, type)`: needs 3+ DONE tasks (with actual minutes) of that type and
  difficulty, else of that type only; otherwise no hint.
- `getDeadlineState(task)` → `DeadlineState` NORMAL / DUE_SOON (48 h) / OVERDUE / DONE.

## Free time and study plan (Part 4)
- `AvailabilityFrame` (320x520, `DISPOSE_ON_CLOSE`, no sidebar) is a helper window opened from
  `StudyPlanFrame` ("My Free Time") without disposing it; `setOnSaved(Runnable)` refreshes the
  caller. Free hours 0-12 in 0.5 steps (stored as minutes, multiples of 30) + `users.rest_day`,
  saved by `AvailabilityService.save` in one transaction (also updates the Session user).
- `StudyPlanFrame`: `tblWeek` has ONE row, 7 columns; each cell is a `DayPlan`
  (painted by `WeekDayRenderer`, headers by `WeekHeaderRenderer` = "Mon 02 Nov" + "planned / free").
  The row height follows the viewport height. `tblDayBlocks` lists the selected day's blocks.
- `engine.PlanGenerator` is pure (no DB): `new PlanGenerator(freeMinutesByDay, restDay)
  .generate(tasks, doneMinutesByTask, usedMinutesByDate, today)` → `PlanResult` (blocks + overloaded).
  Rules: PENDING / IN_PROGRESS only; remaining = estimated − DONE block minutes; order by deadline,
  priority (High first), difficulty (Hard first); window today .. deadline−1 (EXAM: .. deadline);
  30-min chunks; ≤ 120 min per task per day; day capacity = weekday free minutes (rest day 0)
  minus minutes already used; Hard tasks packed early, others round-robin; leftovers → overloaded.
- `StudyPlanService.generatePlan()`: marks overdue tasks MISSED, deletes PLANNED blocks from today on
  (DONE / SKIPPED stay, skipped minutes are planned again), inserts the new blocks in one
  transaction. `summarize(result)` gives the JOptionPane text.
- Mark Block Done (one transaction): block DONE + `study_logs` row (duration = planned minutes,
  breaks 0) + task PENDING → IN_PROGRESS. When no minutes remain the form asks, then
  `completeTask` sets DONE (actual_minutes = studied block minutes if still 0).
- DAOs used in a transaction have a `(Connection, ...)` overload; the normal method delegates to it.
- `Difficulty.fromLabel(label)` turns a table cell label back into the enum.

## Daily check-in (Part 5)
- Model `Checkin`, DAO `CheckinDAO` (one row per user per day, UNIQUE(user_id, checkin_date));
  `CheckinDAO.saveForDay` inserts or updates that row.
- `CheckinService`: `saveToday(stress, energy, mood, sleep, note)` (levels 1-5 required, sleep
  0-14 in 0.5 steps, note ≤ 120 chars, blank = NULL), `getHistory()` (last 14 days, newest first),
  `getStreak()` / static `countStreak(dates, today)` (consecutive days ending today; if today is
  not done yet, the streak ending yesterday still counts). Mood labels: `MOOD_LABELS`
  (1 Very bad … 5 Great). Warning thresholds: stress ≥ 4, energy ≤ 2, sleep < 6 h.
- `users.wellbeing_enabled = 0`: CheckinFrame disables the form and shows the "turned off"
  message; `saveToday` refuses; no reminder.
- Daily reminder: `DashboardFrame` calls `CheckinService.takeDailyReminder()` after it is shown;
  it returns true once per day (stored as an INFO notification) when tracking is on and today has
  no check-in. The JOptionPane offers "Check in now" (opens CheckinFrame) / "Later".

## Analytics engine and risk report (Part 6)
- Pure engine classes (no DB, unit-tested):
  - `WorkloadCalculator(freeMinutesByDay, restDay)`: `studyLoadIndex(tasks, doneMinutesByTask, today)`
    (0-150), `dailyLoad(blocks, tasksById, day)`, static `difficultyWeight`, `deadlineFactor`,
    `taskLoadHours`, `level(index)` → `LoadLevel` LIGHT <50, BALANCED <80, HEAVY ≤100, OVERLOADED.
    Remaining minutes = estimated − DONE block minutes (same as PlanGenerator).
  - `BurnoutRiskCalculator.calculate(wellbeingOn, last3Checkins, logsLast3Days, missedLast7Days,
    loadIndex, previous3Loads)` → `RiskAssessment` (score, `RiskLevel`, `List<RiskReason>`).
    Every point is a `RiskReason` (kind, sentence, points); `getTotalLine()` explains cap / scaling.
    Tracking off → only workload rules, score = points × 100 ÷ 40.
  - `RecommendationEngine.recommend(risk, taskToMove, restDayName)`; last item is always
    `RecommendationEngine.DISCLAIMER`. `pickTaskToMove(tasks)` = lowest priority, latest deadline.
- `RiskService.calculateToday(userId)` → `RiskReport`: loads the data, saves today's
  `risk_snapshots` row (`RiskSnapshotDAO.saveForDay`, one per user per day, reasons as
  "+15 text" lines) and adds at most one BURNOUT (HIGH / SEVERE) and one WORKLOAD (index ≥ 80)
  notification per day. Check-ins used: newest 3 within the last 7 days.
- `RiskService.refreshQuietly()` (errors only logged) is called after login / sign-up, task
  add / update / delete / done, check-in save, plan generation and block done / task complete.
  New services that change tasks, check-ins, study logs or plan blocks must call it too.
- `RiskReportFrame` (900x640, `DISPOSE_ON_CLOSE`, no sidebar): two `util.GaugePanel`s created
  through form "Custom Creation Code" (`new studypulse.util.GaugePanel()`; the field stays
  `JPanel`, cast to `GaugePanel` in code), reasons table, recommendations, disclaimer, 14-day
  history. Opened from the Burnout Risk card ("View details") on DashboardFrame.
- Colors: `UITheme.loadColor(LoadLevel)` / `riskColor(RiskLevel)` – green, amber,
  `ORANGE_RED` (#E8692E), red. `RiskLevel.fromLabel` / `Difficulty.fromLabel` for table labels.
- `UITheme.styleTableWithoutId(table)` for tables that are not database rows.

## Dashboard and analytics (Part 7)
- `AnalyticsService` gives all numbers (no SQL in forms):
  - `getDashboard(userId)` → `DashboardSummary`: today's `RiskReport` (runs `calculateToday`),
    open tasks due in the next 7 days + the next one, study hours this week (Monday → now) vs the
    same part of last week, today's plan blocks, next 5 open tasks, risk scores of the last
    7 days, unread notification count.
  - `getAnalytics(userId, 7 | 28)` → `AnalyticsData`: hours per day (every day, 0 if none),
    load / risk per day (snapshots), sleep / stress per day (check-ins), task counts by status
    (deadline on or after the range start), study hours of the period before, insights.
  - Static, unit-tested insight sentences: `hoursInsight`, `sleepRiskInsight`.
- `DashboardFrame`: header (first name, `formatLong` date, `btnBell` with `UITheme.bellIcon(unread)`),
  four summary cards (`UITheme.styleSummaryCard(panel, color)` = white + 3 px top border in the
  level color), "Today's plan" + `btnStartPomodoro`, "Upcoming deadlines", risk chart in
  `pnlRiskChart` (BorderLayout). Reloads in `formWindowActivated` (and once in the constructor);
  a load error is shown only once so the dialog cannot loop with windowActivated.
- `SidebarUtil.navigate(frame, SidebarUtil.ITEM)` opens a menu screen from any button
  (bell → Notifications, Start Pomodoro → Pomodoro).
- `AnalyticsFrame`: `cmbRange` (Last 7 days / Last 4 weeks), `pnlCharts` = GridLayout 2x2 in the
  form, the four `ChartPanel`s are added in `loadCharts()`; `lblInsight`; `btnExportPng` saves the
  charts as 900x600 PNGs (`studypulse-<chart>-<range>.png`) into a folder from `JFileChooser`.
- `util.ChartUtil`: `barChart`, `lineChart`, `pieChart`, `riskTrendChart` (area fill + latest point
  marked), `panel(chart)` (no zoom / popup), `savePng`. White background, light grid lines, Segoe UI,
  UITheme colors. An EMPTY dataset shows `ChartUtil.NO_DATA` ("Not enough data yet – add tasks and
  check-ins"), so pass an empty dataset when there is nothing meaningful to plot
  (e.g. a trend needs at least 2 days).
- Chart category labels: "Mon 02" (7 days) / "02 Nov" (4 weeks); more than 10 categories are
  rotated 45°.

## Notifications, desktop alerts and Pomodoro (Part 8)
- `NotificationService`:
  - `createOnce(userId, type, message)` – the only way to add a notification: never the same
    message twice on the same day (returns null for a duplicate). `info(userId, msg)` for INFO.
  - `runChecks(userId)` → newly created: WORKLOAD "High workload detected for tomorrow."
    (tomorrow's `dailyLoad` ≥ 100), BURNOUT "Your burnout risk appears to be increasing."
    (4 daily snapshots each higher than the day before), DEADLINE "You have N deadlines in the
    next 48 hours.", DEADLINE "<task> was missed." (once per task, last 7 days).
  - `remindBreak()` → BREAK "Consider taking a short break."; list / filter / `markRead(ids)` /
    `markAllRead()` / `delete(ids)` / `countUnread()` for the logged-in user (ownership checked).
  - `StudyPlanService.generatePlan` adds INFO "Study plan generated: N blocks for M tasks."
- `util.DesktopAlerts`: `start()` after login / sign-up (first check after 2 s, then every
  15 min with a `javax.swing.Timer`), `stop()` on logout. New unread notifications of today are
  shown as `ToastFrame`s (more than 3 → one summary toast) and, when `SystemTray.isSupported()`
  and `user_settings.tray_on`, as `TrayIcon.displayMessage`; `user_settings.notifications_on = 0`
  turns both off (notifications are still stored). `alert(notification)`, `toast(title, msg)` (not
  stored), `addListener` / `removeListener` (DashboardFrame refreshes the bell; it removes its
  listener in `dispose()`).
- `ToastFrame` (300x80 JFrame Form, undecorated, always on top, not focusable, UTILITY type):
  `ToastFrame.showToast(title, message, accentColor)`; bottom-right, stacks upwards, closes after
  4 s or on click.
- `NotificationFrame`: badges `UITheme.notificationColor(type)` (Workload `ORANGE_RED`, Burnout
  `DANGER`, Deadline `PURPLE`, Break `TEAL`, Info `TEXT_MUTED`); unread rows bold + `ROW_UNREAD`
  via `RowColorRenderer.setBoldRows`; multi-select for mark read / delete; times with
  `DateUtil.formatRelative` ("Today 14:05").
- `PomodoroFrame` (360x560, DISPOSE_ON_CLOSE, no sidebar) is a single helper window:
  `PomodoroFrame.showWindow(taskIdOrNull)` (sidebar "Pomodoro" and the dashboard's Start
  Pomodoro use it and do NOT dispose the current screen), `closeWindow()` on logout.
  Phase order = tested `engine.PomodoroCycle` (long break after 4 focus rounds).
  A finished / skipped focus round (≥ 1 min, pauses not counted) → `PomodoroService.saveFocusRound`
  = study_logs row (breaks_taken 0) + task PENDING → IN_PROGRESS + risk refresh.
  More than 120 focus minutes without a finished (not skipped) break → `remindBreak()` + toast.
  Reset / close during focus asks "Save the time you studied so far?".

## Settings and privacy (Part 9)
- `SettingsFrame` (sidebar "Settings") with `tabSettings` (JTabbedPane in the form, one JPanel per
  tab): Profile (name, read-only email, change password), Study preferences (free time → 
  AvailabilityFrame, rest day, Pomodoro minutes, notifications / tray), Privacy, Appearance
  (`rdoLight` / `rdoDark` in `grpTheme`, applied at once), About (team names are plain labels
  `lblTeam1..4` – edit them in Design view).
- `SettingsService`: `getSettings()`, `saveProfile`, `changePassword(current, new, confirm)`
  (rules = `AuthService.checkNewPassword`, new salt), `savePreferences` (users.rest_day +
  user_settings in one transaction), `saveTheme`, `setWellbeingTracking(on, deleteCheckins)`,
  `deleteWellbeingData()` (checkins + risk_snapshots), `exportData(folder)`, `verifyPassword`,
  `deleteAccount(password)` (deletes the users row; everything else goes by ON DELETE CASCADE).
- CSV export (`util.CsvUtil`): tasks.csv, checkins.csv, study_logs.csv, risk_history.csv – ID first,
  header row, UTF-8 with BOM, CRLF, RFC 4180 quoting, text starting with = + - @ gets a leading
  `'` so Excel does not run it as a formula.
- `PomodoroFrame` reads its default minutes from user_settings.
- `util.AppSettings` (java.util.prefs) was removed – all settings live in user_settings.

## Quality rules (Part 10)
- **Errors**: users never see a stack trace or raw SQL text. Services throw
  `new ServiceException("Friendly sentence.", ex)` – the constructor writes the cause to
  `data/error.log` (`util.ErrorLog`) and adds "Details were saved to data/error.log." to the
  message. Never `printStackTrace()` / `System.err`; use `ErrorLog.log(what, ex)`.
  `Main` installs a default uncaught-exception handler (friendly dialog + log).
- **SQL**: only `PreparedStatement` + try-with-resources, also for PRAGMA / DDL; no SQL in forms.
  PRAGMAs that need a table name use the table functions with a parameter
  (`SELECT … FROM pragma_table_info(?)`, see `SchemaDAO`).
- **Startup schema check** (`DatabaseService.checkSchema`, printed by Main):
  "Schema check: 9/9 tables use id INTEGER PRIMARY KEY AUTOINCREMENT" and
  "Index check: 10/10 user_id / task_id columns have an index" – keep both at 100 %.
- **Warnings**: `javac.compilerargs=-Xlint:all,-serial,-rawtypes` (serial / rawtypes only come from
  NetBeans-generated form code). New code must compile without warnings.
- **ID column**: every JTable that shows database rows has ID first. The only exceptions are
  tables that are not rows of a table: `tblWeek` (week grid) and `tblReasons` (Risk Report reasons).
- **Tests**: JUnit 4 in `test/`. DAO tests use a temporary database file
  (`test/studypulse/dao/TestDatabase`, `DBConnection.useDatabaseFile(file)`), never data/studypulse.db.
- **Demo data**: `util.DemoDataSeeder.seed()` (LoginFrame "Load demo data") creates
  demo@studypulse.com / demo123 once; all rows through the DAOs; past risk snapshots are calculated
  with the real engine from the data as it was on that day. Keep it working when the schema changes.
- **Packaging**: Clean and Build → `dist/StudyPulse.jar` + `dist/lib/`; Ant target `package-fat`
  (build.xml) → `dist/StudyPulse-all.jar` + `dist/run.bat`. README has the Launch4j steps.
